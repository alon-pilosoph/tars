What happens when you say “hey TARS”

TARS is a voice assistant for one household. It runs on a Raspberry Pi at home and uses a few cloud services for the hard parts. This page follows one real request from the first word to the follow-up.

Detail
TimeAbout 1.2 sfrom your last word to its first sound. It starts answering before you finish, so the work overlaps. BoundaryNothing leaves the houseuntil a second, stricter check is sure it heard “hey TARS”. Until then the cloud lanes stay closed.
The request we follow

Alon Hey TARS, how long do I boil an egg?

TARS Nine minutes for hard, six for soft.

Alon And for a runny one?

The second question needs no wake word.
One request, second by second

0 is the moment you stop talking

Everything before 0 happens while you are still speaking. That is why the answer comes so fast: by the time you finish, the connections are open, the speaker is known and the reply is already being drafted.

    How it decides it was called

    A fast guess, then a careful check

    Stage 1 is cheap enough to run on every 80 ms of sound, so it is allowed to be a little eager. Stage 2 only runs when stage 1 fires, and it is the one that opens the door.

    Every 80 msA block of sound from the mic
    Stage 1The wake model scores it

    microWakeWord, local, 69 KB. A score of 0.2 or more goes on.

    Close, below 0.2: a near-miss

    Logged, never answered. It may be a missed “hey TARS”.

    How well the generic models do

    Trained on synthetic and converted voices, never on a household member. These are the models every new install starts with. The clips are on Hugging Face.

    Held-out synthetic voices, quiet97%
    Same voices with TV or people talking, 10 to 15 dB92 to 97%
    The owner, whom it never heard, 30 takes97%
    Lookalikes let through, like “hey cars” and “hey stars”0 to 10%
    False answers per hour, an hour of TV and an hour of audiobooks1 and 0 One on the TV hour, when it heard “hey darts”. Stage 1 alone fires about 30 times an hour on TV and 14 on audiobooks; stage 2 turns down all the others.
    When something breaks

    Every stage has a second option

    TARS fails soft, and when it can't recover it tells you in its own voice.

    Stage Normally If that fails
    End of turn Deepgram Flux Local rules
    Speech to text Flux OpenAI transcribes the same recordingA stream that stalls costs one wait, and the backup writes down the rest of that request.
    Brain Qwen on Groq Qwen on Cerebras, then OpenAIIf Groq hasn't started answering within half a second, Cerebras is asked too and the first to answer is kept. A service that fails is skipped for the next two minutes, so an outage doesn't cost every turn its timeout; with both out, OpenAI answers. A reply too long for Groq's cap, like a long note, is written on Cerebras.
    Voice Cartesia Sonic A spoken error line, made at startupA reminder, or how a task on the TV went, waits without its chime and is tried again a minute later.
    Speaker ID WeSpeaker, on the Pi Answered as from an unknown voice
    Wake models The newest trained pair The pair it was installed with
    Mic or speaker The USB speakerphone TARS exits and the system restarts it

    A failed answer is kept in its conversation, with where it failed, and the web UI shows it.

    Under the hood

    Small on purpose

    A process for each job, one folder

    The assistant
    The web UI, FastAPI and React
    Telegram, if it's on
    A backup to S3 every 15 minutes, if it's on
    One SQLite database, WAL mode

    They share the database on the same machine, and a crash in one never takes another down. The backup copies everything to an S3 bucket, and makes room on the card after a month.

    Every stage is an interface

    TriggerTranscriberBrainVoice

    Swapping a cloud service for a local model is one new class and a config change.

    Every answer is measured, every change evaluated

    Each answer is kept with how long each stage took, which model wrote it and, if it failed, where and why. 48 whole conversations, hand-offs followed through, check the brain: 143 of 145 runs right on the 29 measured so far.

    One command checks it all

    voice-assistant --check checks the keys, devices, models, services, the voice and the mic, and says what's wrong and what to do. Once it runs, the web UI's Status page shows much of the same at a glance (as of when it's opened; Refresh brings it up to date): each process by its heartbeat, each service with its key and its own status page, Home Assistant, the backup's last pass, and the Pi's CPU, memory, temperature and disk.

    Hardware

    A Raspberry Pi 4 with 8 GB and a USB speakerphone, an Anker PowerConf.
